# 초기 개발 환경

- Unity Hub와 Unity 6000.3.27f2를 설치했다.
- Android 모듈과 SDK·NDK 설치 완료. Hub에서 OpenJDK도 이미 설치된 상태임을 확인했다.
- 패키지 설정: URP 17.3.0, Input System 1.20.1. 복원과 C# 컴파일을 완료했고 생성된 lock 파일을 함께 관리한다.
- Git 저장소를 초기화하고 Unity 생성물·개인 설정·설치 로그를 제외했다. 원격은 설정하지 않았다.

## 활성화 후 진행

1. Unity Hub에서 로그인하고 무료 Personal 등 자격에 맞는 라이선스를 활성화한다. 무료 버전도 활성화가 필요하다. https://docs.unity.com/en-us/hub/manage-license
2. Hub에서 이 프로젝트 폴더를 추가하고 6000.3.27f2로 연다.
3. 패키지 복원과 컴파일 결과를 확인한다. Input System 활성화 요청이 나타나면 적용하고 재시작한다.
4. `Zombie Survivor > Create Movement Prototype` 메뉴를 실행한다. 기존 열린 씬을 교체하므로 저장할 변경이 없는 상태에서 실행한다.
5. 생성된 Arena 씬에서 Play를 실행해 WASD/방향키 이동과 추적 카메라를 확인한다. 모바일은 화면 왼쪽 드래그 이동을 사용한다.
6. Android 기기를 선정하고 세로 화면·터치 입력을 빌드로 검증한다.

## 현재 검증 한계

최초 실행은 라이선스 부재(198)로 중단됐으나 사용자 활성화 후 재실행에서 라이선스 인식, 패키지 복원, C# 컴파일, Arena 씬·URP 자산 생성이 완료됐다. Unity는 종료 코드 0으로 정상 종료했다. 실제 플레이와 Android 빌드는 아직 미검증이다.

기준 기기는 사용자 확인이 필요하다. 이후 좀비·전투·3분 생존 구현은 게임 설계 문서 순서를 따른다.

## 이동 플레이 모드 검증

`ZombieSurvivor.Editor.VerifyMovement.Run`을 `-batchmode -nographics -executeMethod`로 실행한다. 이 검증은 완료 후 직접 종료하므로 `-quit`을 함께 전달하지 않는다. 예를 들어 다음 인수를 Unity.exe에 전달한다.

```text
-batchmode -nographics -projectPath C:\dev\zombie-survivor -executeMethod ZombieSurvivor.Editor.VerifyMovement.Run -logFile C:\dev\zombie-survivor\unity-movement.log
```

실제 Input System 키보드 상태 이벤트로 W 이동과 키 해제 후 정지, 맵 경계 제한과 카메라 추적을 확인했다. 최종 결과 `MOVEMENT VERIFICATION PASSED`, 종료 코드 0이다. 검증 과정의 포커스 설정은 배치 검증용으로만 적용한다.

Unity 6000.3.27f2의 에디터 검색 인덱스 초기화에서 `UnityEditor.Search.SearchDatabase`의 `ArgumentOutOfRangeException`이 발생했다. 이 특정 에디터 예외는 로그에 남기고 게임 동작 판정에서 제외한다. 다른 Error·Exception·Assert는 실패로 처리한다. 에디터 예외 자체는 해결되지 않았다.

이 검증은 그래픽 화면·터치·Android 기기 성능 확인을 대체하지 않는다.

## 일반 좀비와 피해 처리

Arena에 `EncounterSession`, 플레이어 `Health`, 일반 좀비 프리팹을 연결했다. `NormalEnemy.asset`의 기본 설정은 체력 30, 이동 속도 2, 접촉 피해 10, 접촉 거리 1, 생성 간격 1.5초, 동시 상한 30, 최소 생성 거리 8이다. 플레이어는 체력 100과 피격 후 0.75초 무적 시간을 사용한다. 모두 초기 검증용 수치다.

생성 시 카메라 프러스텀과 여유를 포함한 좀비 경계 상자를 대조하고 맵 내부·최소 거리를 만족하는 위치만 사용한다. 위치를 찾지 못하면 해당 생성을 보류한다. 좀비는 단순 추적과 근거리 분리를 사용하고 사망한 객체를 비활성화해 재사용한다. 사망 집계는 한 번만 수행하며 재사용 시 체력과 상태를 복구한다.

플레이어 사망 시 이동·추적·생성·타이머가 정지한다. 결과의 Restart 또는 R로 플레이어 체력·위치·무적 시간, 적 활성 상태·처치 수·타이머를 초기화한다. 현재는 아래 자동 사격으로 적을 처치할 수 있다.

기존 `VerifyMovement.Run`에 전투 기초 검증을 추가했다. 화면 밖·최소 거리 생성, 추적, 접촉 피해, 반복 피해 차단·무적 종료 후 피해, 중복 사망 집계 방지, 풀 재사용·체력 복원, 동시 상한, 플레이어 사망 정지와 재시작을 확인했다. 최종 `ENCOUNTER VERIFICATION PASSED`, `MOVEMENT VERIFICATION PASSED`, 종료 코드 0이다. 기존 에디터 검색 예외는 같은 기준으로 별도 기록했다.

## 권총·산탄총과 자동 사격

`WeaponSettings` 에셋과 `WeaponController`, 풀링되는 `Projectile`을 추가하고 Arena 플레이어에 연결했다. 임시 총열은 이동 방향과 별개로 조준 방향을 표시한다. 자동 조준은 0.15초 간격으로 사거리 안의 가장 가까운 활성 적을 탐색하고, 발사 직전에도 유효성과 사거리를 확인한다. 적이 없으면 사격하지 않는다.

| 기본 무기 | 피해/발 | 발사 간격 | 사거리 | 투사체 속도 | 발 수·퍼짐 |
| --- | --- | --- | --- | --- | --- |
| 권총 | 15 | 0.45초 | 14 | 25 | 1발 |
| 산탄총 | 10 | 1초 | 8 | 20 | 5발·40도 |

수치는 초기 기본안이며 플레이로 조정한다. 탄약과 재장전은 없고 Space 또는 오른쪽 아래 교체 버튼으로 활성 무기를 전환한다. 활성 무기만 발사하며 무기별 대기시간과 마지막 발사 후 공통 대기시간을 교체 시에도 유지한다. 초기 투사체는 관통 없이 첫 적에게만 피해를 준다. 투사체는 프레임 사이 이동 구간과 적의 충돌 반경을 비교해 빠른 탄환의 통과 누락을 방지하고, 사거리 끝에서 반환한다.

사망 시 발사·투사체 이동이 멈춘다. 재시작하면 활성 투사체·조준 대상·발사 수·대기시간을 초기화하고 권총으로 돌아간다. 이펙트·사운드와 기기별 타격감 조정은 후속 작업이다.

`VerifyMovement.Run`에서 기존 피해 검증 중 자동 사격을 격리한 뒤 무기를 별도로 검증한다. 가장 가까운 적 우선, 권총 두 발 처치·비관통, 교체·반복 교체 연사 우회 방지, 산탄 5발과 여러 적 명중, 사거리 밖·적 부재 시 미발사, 이동 중 자동 사격, Space 전환, 사망 시 발사 정지, 재시작 시 무기·투사체 초기화를 확인했다. `WEAPON VERIFICATION PASSED`, 기존 이동·피해 검증도 PASSED, Unity 종료 코드 0이다. 화면·터치 버튼·Android는 아직 미검증이다.
