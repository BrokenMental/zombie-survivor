# Zombie Survivor 게임 설계

작성일: 2026-11-03  
상태: 초기 설계 v0.1  
프로젝트명: Zombie Survivor (가칭)

## 1. 목표와 결정 상태

몰려드는 좀비 사이에서 생존 경로를 찾고, 무기를 교체하며 적을 처치하는 싱글플레이 액션 게임을 만든다. 첫 단계에서는 이동, 군중 압박, 무기별 차이가 재미있는지 검증한다.

확정 사항:

- Unity로 개발한다.
- 좀비를 피해 이동하며 여러 무기로 전투하는 게임을 만든다.
- 프로젝트 폴더와 설계 문서부터 준비한다.

아래 항목은 논의를 바탕으로 정한 초기 구현 기본안이며, 플레이 검증 후 조정할 수 있다.

- 단순한 형태의 3D 캐릭터와 배경을 사용한다.
- 카메라는 위에서 비스듬히 내려다보며 플레이어를 따라간다.
- 이동은 평면에서 이루어지고 점프나 높낮이 전투는 첫 버전에 포함하지 않는다.
- 모바일 세로 화면을 우선하며, PC 키보드로도 테스트한다.
- 자동 조준·사격과 수동 무기 교체를 사용한다.
- 첫 모바일 검증 대상은 Android로 잡고, iOS는 후속 검토한다.

## 2. 핵심 플레이

플레이 흐름:

1. 플레이어가 기본 무기 2개를 가지고 시작한다.
2. 화면 밖에서 좀비가 나타나 플레이어에게 접근한다.
3. 플레이어는 이동으로 포위를 피하고 무기를 교체하며 공격한다.
4. 적을 처치해 경험치를 모으고 강화 선택으로 성장한다.
5. 시간이 지날수록 무리의 수와 적 구성이 어려워진다.
6. 제한 시간에 등장하는 보스를 처치하면 승리한다. 체력이 0이 되면 패배한다.
7. 결과 화면에서 생존 시간과 처치 수를 확인하고 다시 시작한다.

성장과 보스는 작은 완성 버전에서 추가한다. 첫 프로토타입은 3분 동안 생존하면 성공하는 규칙으로 핵심 전투부터 검증한다.

## 3. 단계별 범위

| 항목 | 첫 프로토타입 | 작은 완성 버전 |
| --- | --- | --- |
| 플레이 시간 | 3분 | 5분 이후 보스전 |
| 맵 | 평평한 테스트 맵 1개 | 간단한 장애물이 있는 맵 1개 |
| 무기 | 권총, 산탄총 | 권총, 산탄총, 기관총, 화염방사기 |
| 적 | 일반형, 빠른형 | 일반형, 빠른형, 탱커형, 보스 1종 |
| 성장 | 없음 | 경험치, 레벨업, 3개 중 강화 선택 |
| 화면 | 시작, 전투, 결과 | 일시정지, 설정, 강화 선택 추가 |
| 저장 | 없음 | 최고 기록과 설정 로컬 저장 |
| 그래픽 | 도형 또는 임시 에셋 | 통일된 스타일의 캐릭터와 효과 |

계정, 서버, 멀티플레이, 랭킹, 광고, 결제, 장비 뽑기, 영구 성장 시스템은 초기 범위에서 제외한다. 필요해지면 별도 설계한다.

## 4. 조작과 카메라

| 기능 | 모바일 | PC 테스트 |
| --- | --- | --- |
| 이동 | 왼쪽 아래 가상 조이스틱 | WASD 또는 방향키 |
| 무기 교체 | 오른쪽 아래 교체 버튼 | Space |
| 사격 | 자동 | 자동 |
| 일시정지 | 상단 버튼 | Esc |

- 무기는 2개를 장착하며 교체 버튼으로 활성 무기를 전환한다.
- 활성 무기만 발사한다. 교체 시 재사용 대기시간을 초기화하지 않는다.
- 사거리 내 가까운 적을 우선 조준하며, 매 프레임 전체 적을 탐색하지 않도록 갱신 간격을 둔다.
- 적이 없으면 사격하지 않는다.
- 이동 방향과 조준 방향을 분리해 도망가면서 뒤쪽 적에게 사격할 수 있게 한다.
- 카메라는 회전하지 않으며, 초기에는 직교 투영을 사용한다. 각도와 화면 범위는 플레이 후 조절한다.
- 화면 아래 조작 영역이 적을 가리지 않도록 배치와 가시 범위를 검증한다.

## 5. 전투와 무기

첫 프로토타입에서는 탄약과 재장전을 생략하고 발사 간격으로 공격 속도를 제어한다. 피격 시 짧은 무적 시간을 두어 여러 좀비가 닿았을 때 즉시 사망하는 현상을 방지한다.

| 무기 | 역할 | 구현 단계 |
| --- | --- | --- |
| 권총 | 단일 적을 안정적으로 처치하는 기본 무기 | 프로토타입 |
| 산탄총 | 짧은 거리에서 부채꼴로 여러 적을 타격 | 프로토타입 |
| 기관총 | 빠른 연사로 한 방향의 적을 지속적으로 처치 | 작은 완성 버전 |
| 화염방사기 | 전방 범위에 지속 피해를 주어 무리를 제어 | 작은 완성 버전 |

무기 데이터는 공격력, 발사 간격, 사거리, 투사체 속도, 탄 수, 퍼짐각, 관통 수, 넉백으로 구성한다. 범위 공격은 공격 주기와 범위도 별도로 정의한다. 수치는 플레이 테스트로 결정한다.

타격감은 피격 색 변화, 짧은 넉백, 총구 효과, 사운드로 먼저 검증한다. 과도한 화면 흔들림과 지속적인 이펙트로 적의 위치가 가려지지 않게 한다.

## 6. 적과 웨이브

- 일반형: 기본 속도로 플레이어에게 접근한다.
- 빠른형: 체력은 낮고 속도가 빨라 이동 경로를 바꾸게 한다.
- 탱커형: 느리지만 체력이 높아 이동 경로를 막는다.
- 보스: 공격 전조가 있는 돌진 또는 범위 공격을 사용한다. 첫 보스는 패턴 1~2개로 제한한다.

첫 맵에서는 플레이어 방향으로 단순 추적하고, 가까운 적끼리 약하게 밀어내어 한 점에 겹치지 않게 한다. 장애물 추가 단계에서 경로 탐색 방식과 비용을 검토한다.

적은 카메라 가시 영역 밖에서 생성하며 맵 경계와 플레이어 최소 거리를 확인한다. 시간대별 생성 간격, 적 구성, 동시 생존 상한을 웨이브 데이터로 관리한다. 상한에 도달하면 추가 생성을 보류하고, 상한만으로 난이도를 조절하지 않는다.

## 7. 성장과 종료 조건

작은 완성 버전부터 적이 경험치 아이템을 떨어뜨리며, 플레이어가 근처에 접근하면 수집한다. 레벨업 시 전투를 멈추고 3개의 강화 중 하나를 선택한다.

초기 강화 후보는 공격력, 발사 속도, 이동 속도, 최대 체력, 수집 범위다. 강화별 최대 단계와 선택 가능 조건을 데이터로 정의한다. 모든 후보가 최대 단계일 때는 회복 같은 대체 보상을 제공한다.

- 프로토타입 승리: 3분 생존.
- 작은 완성 버전 승리: 5분 시점에 등장하는 보스 처치. 5분 도달만으로 종료하지 않는다.
- 패배: 플레이어 체력 0.
- 결과: 승패, 생존 시간, 처치 수를 표시한다.
- 재시작: 적, 투사체, 타이머, 강화, 플레이어 상태를 초기화한다.

## 8. 기술 구성

| 항목 | 기본안 |
| --- | --- |
| 엔진 | Unity, 프로젝트 생성 시 지원 중인 LTS의 정확한 버전 고정 |
| 언어 | C# |
| 렌더링 | URP 기반 3D |
| 입력 | Unity Input System, 이동·교체·일시정지 액션 분리 |
| 설정 데이터 | ScriptableObject로 무기·적·웨이브·강화 정의 |
| 저장 | 작은 완성 버전에서 버전 필드를 가진 로컬 저장 데이터 사용 |
| 서버 | 초기 버전에서는 사용하지 않음 |

권장 코드 책임:

- GameSession: 시작, 플레이, 강화 선택, 일시정지, 결과 상태와 타이머.
- PlayerController: 이동 입력과 이동 처리.
- Health: 체력, 피해, 무적 시간, 사망 이벤트.
- WeaponController: 장착, 교체, 자동 조준, 발사 주기.
- EnemyController: 추적, 접촉 공격, 사망 처리.
- WaveDirector: 시간에 따른 적 생성과 동시 개체 수 관리.
- PoolService: 적, 투사체, 반복 이펙트 재사용.
- ExperienceSystem: 경험치 수집과 강화 선택.
- HUD / ResultUI: 체력, 시간, 무기, 처치 수와 결과 표시.
- SaveService: 최고 기록 및 설정 저장·복원.

ScriptableObject는 기본 설정으로 사용하고, 플레이 중 체력이나 강화 값은 실행 시 인스턴스에 보관한다. 게임 상태에 맞춰 이동·발사·웨이브 시간이 함께 멈추고 재개되도록 한다.

Unity 프로젝트 생성 후 권장 디렉터리:

```text
Assets/_Game/
  Scenes/
  Scripts/
    Core/
    Player/
    Combat/
    Enemies/
    Progression/
    UI/
    Save/
  Data/
  Prefabs/
  Art/
  Audio/
  Tests/
docs/
```

씬은 우선 Boot와 Arena로 최소화한다. Unity 버전과 패키지 버전을 고정하고, 프로젝트 생성 시 Assets의 .meta 파일과 Packages, ProjectSettings를 버전 관리에 포함한다. Library, Temp, Logs 및 빌드 출력은 제외한다.

## 9. 성능과 검증

성능 수치는 목표이며 아직 측정 결과가 아니다. 기준 Android 기기는 프로젝트 초기 설정 단계에서 선정한다.

- 목표 기기에서 60fps를 지향한다.
- 좀비 100마리를 기준으로 측정하고, 200마리 안팎까지 점진적으로 확대한다.
- 적, 투사체, 반복 이펙트에 오브젝트 풀을 적용한다.
- 조준과 근접 탐색은 갱신 주기를 제한하고, 측정 결과에 따라 공간 분할을 적용한다.
- 좀비마다 복잡한 물리 시뮬레이션이나 실시간 그림자를 부여하지 않는다.
- 에디터 수치와 실제 휴대폰 결과를 구분하며 CPU, GPU, 메모리와 발열에 따른 프레임 저하를 확인한다.

프로토타입 완료 기준:

1. 시작부터 3분 생존 또는 사망, 결과, 재시작까지 진행할 수 있다.
2. 이동하면서 자동 공격하고 두 무기를 교체할 수 있다.
3. 권총과 산탄총의 효과적인 사용 상황이 구분된다.
4. 적이 화면 밖에서 생성되고 플레이어를 추적하며 피해를 주고받는다.
5. 무기 교체 반복으로 발사 간격을 우회할 수 없다.
6. 재시작 후 이전 적·투사체·점수·타이머가 남지 않는다.
7. 적 100마리 조건의 기기별 성능을 기록한다.

후속 검증은 일시정지와 앱 복귀, 강화 선택 중 전투 정지, 보스 승패, 저장 복원을 포함한다. 자동 테스트는 피해·무적 시간, 무기 발사 주기, 상태 전환 등 오류가 게임 규칙에 영향을 주는 부분에 집중한다.

## 10. 구현 순서

1. Unity 버전과 기준 기기 확정, URP 프로젝트 및 입력 설정.
2. 평면 맵, 플레이어 이동, 고정 각도 추적 카메라.
3. 일반 좀비 생성·추적, 체력과 피해 처리.
4. 권총·산탄총, 자동 조준, 무기 교체.
5. 빠른 좀비, 웨이브, 3분 타이머, 결과와 재시작.
6. 실제 기기 성능 측정과 조작·타격감 조정.
7. 재미가 확인되면 경험치, 강화, 추가 무기, 탱커, 보스 구현.
8. 그래픽·사운드 통일, 설정·저장, 배포 검증.

## 11. 다음 단계에서 정할 항목

- 정확한 Unity 에디터 버전과 설치 모듈.
- 기준 Android 기기와 최소 지원 범위.
- 그래픽 분위기: 밝은 장난감 스타일 또는 어두운 생존 분위기.
- 임시 에셋을 직접 제작할지 외부 에셋을 사용할지.
- 첫 플레이 테스트를 통한 카메라 거리, 이동 속도, 무기 수치.

외부 에셋을 도입하면 출처와 사용 조건을 함께 기록한다. 에셋 제작과 학습 시간을 확인하기 전에는 전체 출시 일정을 확정하지 않는다.
